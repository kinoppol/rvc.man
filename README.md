# ระบบคู่มือการปฏิบัติงาน วิทยาลัยอาชีวศึกษาร้อยเอ็ด

เว็บแอปสำหรับเปิดอ่านและค้นหา **คู่มือการปฏิบัติงาน** ของวิทยาลัยอาชีวศึกษาร้อยเอ็ด
ออกแบบให้ใช้งานสะดวกบนโทรศัพท์มือถือเป็นหลัก (mobile-first) และติดตั้งเป็นแอปบนหน้าจอได้ (PWA)

- **Backend:** PHP 8 (ทดสอบบน 8.2) + PDO — ไม่ใช้ Composer หรือเฟรมเวิร์กใด ๆ
- **ฐานข้อมูล:** MariaDB 10 (ทดสอบบน 10.4) charset `utf8mb4`
- **เข้าใช้งาน:** `http://localhost/rvc.man/`

---

## การติดตั้ง

1. เปิด Apache และ MySQL ใน XAMPP
2. เปิด `http://localhost/rvc.man/install.php` ในเบราว์เซอร์
3. กรอกข้อมูลการเชื่อมต่อฐานข้อมูลและบัญชีผู้ดูแลระบบ แล้วกด **ติดตั้งและนำเข้าข้อมูลคู่มือ**
4. ลบไฟล์ `install.php` ออกเมื่อใช้งานจริง

ติดตั้งผ่านบรรทัดคำสั่งได้เช่นกัน (ใช้ค่าใน `config/config.php` เดิม และสร้างบัญชี `admin` / `admin1234`):

```bash
C:/xampp2/php/php.exe install.php
```

> การติดตั้ง **ลบและสร้างตารางใหม่ทั้งหมด** ตาม `sql/schema.sql`

### นำเข้าข้อมูลซ้ำ

ไฟล์ต้นฉบับอยู่ที่ `data/manual-source.md` เมื่อแก้ไขไฟล์แล้วสั่งนำเข้าใหม่ได้จาก
หน้า **ผู้ดูแลระบบ → นำเข้าข้อมูล** หรือ

```bash
C:/xampp2/php/php.exe bin/import.php
```

การนำเข้าเป็น idempotent — ฝ่าย/งานจับคู่ด้วยชื่อ และเรื่องจับคู่ด้วย (งาน, ชื่อเรื่อง)
รันซ้ำจึงเป็นการ *ปรับปรุง* ข้อมูลเดิม ไม่ใช่สร้างซ้ำ

ตรวจผลการแยกวิเคราะห์ไฟล์ต้นฉบับโดยไม่แตะฐานข้อมูล:

```bash
C:/xampp2/php/php.exe bin/parse-check.php
```

## ความสามารถ

**ส่วนผู้ใช้ทั่วไป** (ไม่ต้องเข้าสู่ระบบ)

- หน้าแรกพร้อมช่องค้นหา สถิติ และเรื่องที่เปิดดูบ่อย
- เรียกดูตามโครงสร้าง **ฝ่าย → งาน → เรื่อง**
- หน้าเรื่องแสดง หน้าที่และความรับผิดชอบ, ขั้นตอนการปฏิบัติงานแบบไทม์ไลน์,
  ตารางผู้รับผิดชอบ/หลักฐาน, ไฟล์แนบ, ลิงก์เรื่องก่อนหน้า–ถัดไป และปุ่มพิมพ์/แชร์
- ค้นหาภาษาไทยพร้อมไฮไลต์คำค้น กรองตามฝ่าย และแบ่งหน้า
- หน้าข้อมูลทั่วไปของวิทยาลัย (บทนำของคู่มือ)
- โหมดสว่าง/มืด ตามเครื่องหรือเลือกเอง

**ผู้ใช้ที่เข้าสู่ระบบ** — บันทึกเรื่องที่ใช้บ่อย และเปลี่ยนรหัสผ่าน

**ผู้ดูแลระบบ** — ภาพรวมระบบ, เพิ่ม/แก้ไข/ลบเรื่องพร้อมขั้นตอนและผังงาน,
แนบไฟล์, จัดการฝ่าย/งาน, หน้าข้อมูลทั่วไป, ผู้ใช้งาน และนำเข้าข้อมูลจากไฟล์ต้นฉบับ

```

  Repository.php     SQL ทั้งหมดของระบบอยู่ที่นี่

  Importer.php       เขียนผลจาก parser ลงฐานข้อมูล
  helpers.php        h(), url(), CSRF, flash, icon() ฯลฯ
  controllers/       PublicController, AuthController, AdminController
```

## รายละเอียดทางเทคนิคที่ควรทราบ

### การค้นหาภาษาไทย

ภาษาไทยไม่มีการเว้นวรรคระหว่างคำ MariaDB FULLTEXT จึงแบ่งคำไม่ได้
ระบบจึงเก็บคอลัมน์ `procedures.search_text` ที่ถูกบีบให้เหลือเฉพาะตัวอักษร
(ตัดช่องว่างและเครื่องหมายวรรคตอนออกด้วย `ManualParser::key()`) แล้วค้นด้วย `LIKE`
คำค้นถูกบีบด้วยวิธีเดียวกัน ทำให้คำที่ถูกตัดบรรทัดกลางคำในต้นฉบับยังค้นเจอ
คำค้นหลายคำ (คั่นด้วยช่องว่าง) ต้องพบครบทุกคำ

### การซ่อมข้อความไทยจากไฟล์ต้นฉบับ

`data/manual-source.md` เป็นผลจากการแปลง PDF จึงมีความเสียหายเชิงระบบ 3 แบบ
ซึ่ง `ManualParser::normalize()` ซ่อมให้ก่อนนำเข้า

| อาการ | ตัวอย่าง | วิธีซ่อม |
| --- | --- | --- |
| `ำ` ถูกแยกเป็นช่องว่าง + `า` | `ทำ` → `ท า` | `า` ขึ้นต้นคำไม่ได้ จึงรวมกลับเป็น `ำ` เสมอ |
| วรรณยุกต์ `่` `้` กลายเป็นสระ `ุ` `ู` | `ฝ่าย` → `ฝุาย` | `ุา` / `ูา` ไม่ใช่ลำดับที่ถูกต้อง จึงแทนกลับได้ |
| สระ/วรรณยุกต์ลอยมาก่อนพยัญชนะ | `บันทึก` → `ับนทึก` | สลับเฉพาะกรณี *ไม่มีพยัญชนะรองรับ* เท่านั้น เพื่อไม่ให้ `ไม่รวม` เพี้ยนเป็น `ไมร่วม` |

ยังเหลือคำที่เพี้ยนอยู่บ้างในต้นฉบับ (ประมาณ 50 จุดจากทั้งเล่ม) แก้ไขได้จากหน้า
**ผู้ดูแลระบบ → จัดการเรื่อง**

### การแยกโครงสร้างจากต้นฉบับ

ไฟล์ต้นฉบับไม่มีหัวข้อ Markdown เลย โครงสร้างจึงถูกกู้จากองค์ประกอบของหน้ากระดาษ
ที่ซ้ำกันทุกเรื่อง — บรรทัดชื่อฝ่าย, บรรทัดชื่องาน + ชื่อเรื่อง, ตารางผังงาน
และเลขหน้าท้ายกระดาษ (ใช้แบ่งหน้า)

- ตารางผังงานอ่านแบบ **อิงตำแหน่งคอลัมน์** โดยจำ index ของ `ผู้รับผิดชอบ` / `หลักฐาน`
  จากแถวหัวตาราง ไม่อ่านช่องข้างเคียง เพราะช่องข้างเคียงคือลูกศรและกล่องผังงาน
  ซึ่งให้ผลลัพธ์ที่ดูสมเหตุสมผลแต่ผิด
- ขั้นตอนอ่านจากข้อความหลังหัวข้อ `ขั้นตอน…` ถ้าไม่มีหัวข้อนี้จะเลือก
  "ลำดับเลขที่ยาวที่สุดและต่อเนื่อง" แทน เพื่อตัดเศษเลขจากผังงานออก
- ผลปัจจุบัน: **4 ฝ่าย / 27 งาน / 122 เรื่อง / 1,354 ขั้นตอน**

### ความปลอดภัย

- ทุก POST ตรวจ CSRF token (`verify_csrf()`) — ทุกค่าที่แสดงใน view ผ่าน `h()`
- รหัสผ่านเก็บด้วย `password_hash()` และ regenerate session id เมื่อเข้า/ออกระบบ
- `.htaccess` ปิดการเข้าถึง `app/ config/ sql/ views/ storage/ bin/ data/` โดยตรง
  และไฟล์ `.sql` `.md` ไฟล์แนบดาวน์โหลดผ่านเส้นทาง `/attachment/{id}` เท่านั้น
- `install.php` เป็นสคริปต์ทำลายข้อมูลและไม่มีการยืนยันตัวตน — **ต้องลบเมื่อใช้งานจริง**

### รองรับอุปกรณ์เคลื่อนที่

- ออกแบบแบบ mobile-first: แถบเมนูล่าง (bottom tab bar) บนมือถือ
  เปลี่ยนเป็นเมนูด้านข้างเมื่อจอกว้าง ≥ 1000px
- เป้าการแตะขนาดอย่างน้อย 44px, รองรับ `env(safe-area-inset-*)` สำหรับจอมีรอยบาก
- ตารางผู้รับผิดชอบ/หลักฐานแสดงเป็นการ์ดบนมือถือ และเป็นตารางบนจอกว้าง
- PWA: `manifest.webmanifest` + `sw.js` (network-first สำหรับหน้าเว็บ, cache-first สำหรับ asset)
  หน้าที่เคยเปิดแล้วยังอ่านได้เมื่อออฟไลน์ — ยกเว้นหน้า `/admin` ที่ไม่ถูก cache
- มีสไตล์สำหรับสั่งพิมพ์ (ซ่อนเมนูและปุ่มทั้งหมด)
